# dotenv

<ApiMeta addedVersion="2.1.0" />

Load environment variables from `.env` files and expose them to your source code via both [`import.meta.env`](/plugins/webpack/define-plugin#import-meta-env) and [`process.env`](/plugins/webpack/define-plugin#process-env).

- **Type:**

```ts
type Dotenv = boolean | DotenvPluginOptions;

interface DotenvPluginOptions {
  /**
   * The directory from which .env files are loaded. Can be an absolute path,
   * `false` will disable the .env file loading.
   */
  dir?: false | string;
  /**
   * Only expose environment variables that start with these prefixes.
   * Defaults to 'WEBPACK_'.
   */
  prefix?: string | string[];
  /**
   * Template patterns for .env file names. Use [mode] as a placeholder for
   * the rspack mode.
   */
  template?: string[];
}
```

- **Default:** `false`

## Usage

Enable with the defaults by setting `dotenv` to `true`:

```js title="rspack.config.mjs"
export default {
  dotenv: true,
};
```

Or pass an options object:

```js title="rspack.config.mjs"
export default {
  dotenv: {
    prefix: 'APP_',
    template: ['.env', '.env.[mode]'],
  },
};
```

When enabled, Rspack loads `.env` files from [`context`](/config/context) (or [`dir`](#dir) when set), exposes every matching variable as `import.meta.env.KEY` **and** `process.env.KEY`.

```js title="src/index.js"
// .env: APP_API_URL=https://example.com
console.log(import.meta.env.APP_API_URL); // 'https://example.com'
console.log(process.env.APP_API_URL); // 'https://example.com'
```

:::info
Like [`EnvironmentPlugin`](/plugins/webpack/environment-plugin), env values are strings. Rspack converts them to string literals for you, so you do **not** need to wrap them with `JSON.stringify`.
:::

## dotenv.dir

<PropertyType
  type="false | string"
  defaultValueList={[{ defaultValue: 'context' }]}
/>

The directory from which `.env` files are loaded. Can be an absolute path. Set to `false` to disable loading `.env` files entirely (only `process.env` is then used).

## dotenv.prefix

<PropertyType
  type="string | string[]"
  defaultValueList={[{ defaultValue: "'WEBPACK_'" }]}
/>

Only expose environment variables whose name starts with one of the given prefixes.

```js title="rspack.config.mjs"
export default {
  dotenv: {
    prefix: 'APP_',
  },
};
```

Use an array to match multiple prefixes:

```js title="rspack.config.mjs"
export default {
  dotenv: {
    prefix: ['APP_', 'PUBLIC_'],
  },
};
```

## dotenv.template

<PropertyType
  type="string[]"
  defaultValueList={[
    { defaultValue: "['.env', '.env.local', '.env.[mode]', '.env.[mode].local']" },
  ]}
/>

Template patterns for `.env` file names. Use `[mode]` as a placeholder for the current rspack [`mode`](/config/mode) (defaults to `development`). Files are loaded in order and later values override earlier ones.

```js title="rspack.config.mjs"
export default {
  mode: 'production',
  dotenv: {
    template: ['.env', '.env.[mode]'],
  },
};
```

With `mode: 'production'`, this loads `.env` and then `.env.production`.

## Variable expansion

Values may reference other variables using `$VAR` or `${VAR}` syntax. References resolve against `process.env` and the already-parsed `.env` values:

```bash title=".env"
API_HOST=127.0.0.1
API_URL=http://${API_HOST}:8080
```

`import.meta.env.API_URL` resolves to `http://127.0.0.1:8080`.

:::tip
Variables already present in `process.env` take precedence over the values parsed from `.env` files.
:::

## Precedence

Environment definitions are merged from several sources. Within a single key, later registrations override earlier ones:

1. User plugins applied in your config (e.g. [`EnvironmentPlugin`](/plugins/webpack/environment-plugin), user [`DefinePlugin`](/plugins/webpack/define-plugin) with `import.meta.env.*` / `process.env.*` keys).
2. `dotenv` (this option).
3. `NODE_ENV`, derived from [`optimization.nodeEnv`](/config/optimization#optimizationnodeenv) (which defaults to [`mode`](/config/mode)).

All of these feed a single accumulated env object that is exposed as `import.meta.env` and mirrored onto `process.env.KEY` per-key. See [DefinePlugin — `import.meta.env`](/plugins/webpack/define-plugin#import-meta-env) for the replacement semantics.
