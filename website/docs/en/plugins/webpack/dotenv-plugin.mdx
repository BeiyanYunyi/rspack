# DotenvPlugin

<ApiMeta addedVersion="2.1.0" />

`DotenvPlugin` loads environment variables from `.env` files and exposes them to your source code via both [`import.meta.env`](/plugins/webpack/define-plugin#import-meta-env) and [`process.env`](/plugins/webpack/define-plugin#process-env). Every matching variable is inlined at compile time, so unused variables are tree-shaken away.

It is the same plugin that the [`dotenv`](/config/dotenv) config option enables — you can apply it directly when you need to control it from a plugin:

```js title="rspack.config.mjs"
import { DotenvPlugin } from '@rspack/core';

export default {
  plugins: [new DotenvPlugin({ prefix: 'APP_' })],
};
```

is equivalent to:

```js title="rspack.config.mjs"
export default {
  dotenv: { prefix: 'APP_' },
};
```

## Options

- **Type:**

```ts
interface DotenvPluginOptions {
  /**
   * The directory from which .env files are loaded. Can be an absolute path,
   * `false` will disable the .env file loading.
   */
  dir?: false | string;
  /**
   * Only expose environment variables that start with these prefixes.
   * Defaults to 'WEBPACK_'.
   */
  prefix?: string | string[];
  /**
   * Template patterns for .env file names. Use [mode] as a placeholder for
   * the rspack mode.
   */
  template?: string[];
}
```

See [`dotenv`](/config/dotenv) for the full reference of `dir`, `prefix`, `template`, variable expansion and precedence behavior.

:::info
Env values are strings. Rspack converts them to string literals for you, so you do not need to wrap them with `JSON.stringify`.
:::
